## 第一部分 · 产品定位

### 一句话
知伴是一个**个人信息中枢**：把你散落在各处的"收、发"信息（社交软件、通话、语音、日历）自动采集进来，用一套**核心数据骨架**串起来，基于场景（第一个是**个人 CRM**）判断哪些信息有用，进而生成日程/待办/提醒去驱动你行动，并在你授权的范围内**替你在手机各 App 里把事情办完**——小到回一条消息、做一份报价，大到在某个 App 里帮你操作。

### 灵魂不是"记录"，是"判断 + 驱动"
- 真正价值：agent 替你想"这条信息意味着该做什么"，并推动你去做。
- 护城河：**核心数据骨架沉淀出的上下文**。它把你和每个人、每件事的来龙去脉越攒越准。上下文脏了，一切上层判断都错——**"采集判断不挂错联系人"是最高质量红线**。

### 核心数据骨架 = 三体 + 一条事件时间线
骨架回答 agent 判断所需的四个问题：

| 柱子 | 回答 | 是什么 |
|---|---|---|
| **联系人 Contact** | 谁 | 姓名、电话、公司、多身份/别名 |
| **关系图谱 Relation** | 什么关系 | 与某人的多条关系边（同事/客户/亲友…） |
| **事件 Event（时间线）** | 发生过什么 | 聊过的事、通过的话、见过面、成交的单、日历里已发生的事 |
| **日程/待办 Schedule** | 该做什么 | 将要发生的会议、提醒、待办 |

- 日历事件只是"事件"的一种；"聊过的、通过话的、成交的"都是事件。
- agent 的"判断" = 这个人(Contact) × 跟我这关系(Relation) × 刚发生了这事(Event) → 该在那个时间做那事(Schedule)。
- **演进方向**：把事件收敛成一条统一时间线（当前分散在关系事件/事实/CRM 活动/日历几处），让"和谁、何时、发生了什么"成为一等查询。

### 自主干活（Act）是一个开放能力，不是几个功能
"回消息、做报价、点外卖"不是三个功能，是**同一件事的实例**：agent 基于已掌握的上下文，替你在对应 App 里把动作完成。按**执行机制 + 风险**分三层红线：

| 层 | 例子 | 执行方式 | 红线 |
|---|---|---|---|
| 对内 · 可回滚 | 建日程、记 CRM、合并联系人 | 直接写库 | 显而易见的可自动；写错可改/可回滚 |
| 对外 · 发文字 | 回消息、发报价 | 生成草稿 → `ACTION_SEND` 分享 → **用户点发送** | 发出收不回，用户按最后一下 |
| 在第三方 App 动手 | 点外卖、下单 | 无障碍操作界面 / 深链 | 多涉及花钱/不可逆，**全程可见、逐步确认** |

- 对外**不做无障碍自动代发**，用标准 `ACTION_SEND` 让用户把关。
- 越往"操作第三方 App、涉及花钱"走，越要用户盯着——不是技术做不到自动，是"发错/点错收不回"的产品代价。

### 分发形态：当前按侧载设计
知伴当前面向愿意明确授权通知监听、无障碍和通话记录的重度用户（销售/商务/管理者），按**侧载 + 用户清楚授权**设计。`READ_CALL_LOG` 是 hard-restricted 权限，不能仅凭 Manifest 和普通运行时弹窗假设一定可用；每种安装渠道都必须真机验证安装器允许名单和最终授权状态。Google Play 仅接受默认电话/助手或少量经审核的例外，个人 CRM 不按"企业 CRM + 企业登录"例外规划。无障碍服务描述保持克制诚实（不点击、不代发、不读历史、截图不保存）。

## 第二部分 · 概念模型（先懂这套语言，再读代码）

| 概念 | 定义 | 代码落点 |
|---|---|---|
| 候选 Candidate | 采集进来、还没定论的一条信息（等匹配/等确认） | `notification_candidates` |
| 事实 Fact | 从候选提炼出、已确认的一条知识（如 CURRENT_MATTER 当前事项） | `facts` |
| 记忆 Memory | 用户确认后长期保留的偏好/事实 | `memory_*` |
| 关系边 RelationshipEdge | 两个联系人之间的一类关系 + 置信度 + 是否用户确认 | `relationship_edges` |
| 合并 Merge | 把疑似同一人合并，可撤销 | `contact_merge_links` |
| 事件 Event | 与某人/某事相关的一次来往 | `relationship_events` / `call_records` / `call_notes` / `crm_activities` |
| 场景 Scene | 一类可插拔的应用能力（第一个：个人 CRM） | `SceneCapability` |
| 技能 Skill | 一组触发意图 + 所需工具 + 规划指令（SYSTEM/SCENE 两级） | `SkillContracts` |
| 工具 Tool | agent 可调用的原子能力（读/写日历、联系人、CRM…） | `*ToolBinding` |
| 计划 Plan | 一次多步任务的 DAG | `PlanLifecycle`（roadmap） |
| 运行 Run / 尝试 Attempt | 一次 agent 执行及其重试单位 | `runtime_runs` / `runtime_attempts` |
| 租约/防护 Lease/Fencing | 会话执行的互斥与代际戳，防并发/重放 | epoch fencing |

## 第三部分 · 技术架构

### 技术栈
Kotlin + Jetpack Compose (Material 3) + Hilt + Room (SQLCipher) + OkHttp + Coroutines/Flow + DataStore + WorkManager + Coil + Navigation Compose + ML Kit 中文 OCR。
`minSdk 26 / compileSdk 35`，AGP 8.7.3，Kotlin 2.1.0，JVM 17。**全工程零 Log/Timber**（生产日志纪律）。

### 模块结构（多模块 Gradle，骨架先行）
原则：`app` 是唯一 Android 应用与主要集成层；Agent 的契约、策略、状态机等可复用核心拆进子模块，Android 系统接入、Room 持久化和生产编排留在 `app`。除 `agent:provider` 是 Android Library 外，其余 Agent 子模块当前为 Kotlin/JVM 模块。

```
:app                                ← Android 应用 + DI 装配 + UI + 系统服务 + Room
├── :agent:contracts                ← 契约/SPI（出境策略接口、敏感度/用途/通道枚举）
├── :agent:provider  → api(contracts)← Android Library；出站策略 + Provider 适配 + 凭据保管
├── :agent:context                  ← 上下文检索/装配（PromptAssembler、FTS-only Embedding）
├── :agent:tools                    ← 工具契约 + 幂等键
├── :agent:governance → impl(tools) ← ActionPolicy（风险分级）；ChangeLog/DomainWriter 仍在 app 集成层
├── :agent:runtime   → api(contracts)← 内核状态机 RuntimeStateMachine、Plan 抽象
├── :agent:memory                   ← MemoryGate 契约
├── :agent:mcp                      ← MCP 客户端 + StreamableHttpMcpTransport
├── :agent:skills                   ← SkillContracts（技能定义）
└── :agent:feature-ask              ← 问问对话页 UI State 契约
```

- **边界守卫**：根 `build.gradle.kts` 的 `verifyAgentModuleBoundaries` 已挂根 `check`，按模块逐项配置扫描根和禁止依赖。它不是自动覆盖所有 `agent/*` 的通配规则；新增模块或移动源码时必须新增/更新对应 Rule，并由 Gradle 模块依赖共同约束边界。

### 为什么是 10 个 Agent 子模块
把"agent 的大脑"（想清楚 + 做决定 + 发出去）从"Android 的壳"（界面、系统服务、数据库、权限）分开。好处：① 最难对的部分（状态机、策略、检索）可在 JVM 快速单测；② 边界强制"大脑"不被"壳"污染；③ 加新场景/通道时在对应子模块里加，不动壳。

### 导航骨架（`navigation/NavGraph.kt`）
单 NavHost，Type-Safe 路由（`@Serializable`），`startDestination = Calendar`。
主 TAB：**今日/日历、关系、能力、我的**；独立对话页：**问问**。

## 第四部分 · 数据模型（Room + SQLCipher）

### 库与迁移
单一 `AgentDatabase`（多版本 schema，迁移全链注册、无 `fallbackToDestructive`、无版本空洞）。导出 schema 在 `app/schemas/`，迁移有 androidTest 覆盖。

### 主要表（按骨架归组）
| 骨架 | 表 |
|---|---|
| 联系人 | `contacts`、`contact_platform_identities`、`contact_aliases`、`contact_methods` |
| 关系 | `relationship_edges`、`contact_merge_links` |
| 事件 | `relationship_events`、`call_records`、`call_notes`、`facts`、`crm_activities`（以查询投影组成统一时间线） |
| 日程 | `schedules` |
| CRM | `crm_leads`、`crm_opportunities`、`crm_opportunity_stakeholders`、`crm_activities`、`crm_next_actions`、`crm_agent_suggestions`、`crm_stage_history` |
| 采集 | `notification_candidates`、`call_records`、`call_notes` |
| 记忆 | `memory_namespaces`、`memory_records`、`memory_current_versions`、`memory_evidence`、`memory_tombstones`、`memory_fts`(FTS 虚表) |
| 运行时 | `runtime_sessions`、`runtime_runs`、`runtime_attempts`、`runtime_command_inbox`、`runtime_events`、`runtime_tool_executions`、`runtime_run_inputs` |
| 治理 | `change_log`（可撤销写，before/after digest + inversePayload） |
| 出站审计 | DataStore `outbound_data_audit`（非 Room） |

### 数据一致性约定
- 多表写一律 `database.withTransaction{ }`。
- 外键 + 级联：CRM（机会→干系人/活动/动作/建议/阶段史）按 CASCADE 正确排序；软删联系人需级联处理关联。
- 删除遵循领域约定：记忆使用 tombstone；联系人使用 `deletedAtEpochMs`；关系、事件等使用状态字段。删除必须同步撤销或过滤 FTS、向量和其它检索投影。
- 合并检索统一排除 `contact_merge_links WHERE undoneAtEpochMs IS NULL`（撤销后恢复）。

## 第五部分 · Agent 运行时（内核）

### 调度模型
"DB 命令表 + 会话租约 + 协程循环"：
- `RuntimeCommandRunner`：conflated Channel + 指数退避消费 inbox。
- `KernelCommandProcessor`：抢会话租约 → 按 Start/Retry/Approve/Cancel 分发。
- `RuntimeStateMachine`（agent/runtime）：14 信号 × 12 状态纯函数 reduce，构成 ReAct 回环。
- 持久化：事件溯源 + 幂等 eventId + 租约 fencing(epoch) + CAS；生产崩溃恢复由 `ProviderExecutionEngine.recoverNext()` 与 `RoomRuntimeStore` 协作完成。
- **取消语义**：关键 suspend 链路显式 `catch (c: CancellationException){ throw c }`，不用 `runCatching` 吞取消。

### 上下文装配（context 模块）
`RoomContextRetrievalPipeline` 多路并行（联系人/日程/记忆/事实 本机 FTS + 可选向量）→ RRF 融合 → token 预算裁剪 → `PromptAssembler` 组装（每块带 trust + sensitivity + provenance）。检索失败走 `attemptRetrieval`：区分 `path:timeout` / `path:failure`，rethrow 取消，产出固定降级码。

### Provider 与工具
- **LLM**：StepFun（OpenAI 兼容，`OpenAiCompatibleProviderAdapter`）。
- **Embedding**：火山 Ark `VolcEmbeddingEnvironment` 已实现；生产注入 `FtsOnlyEmbeddingGateway`（本机 FTS），远程向量待接。
- **ASR**：StepFun（`StepFunCloudAsrTransport` 批量 / `StepFunRealtimeVoiceController` 实时，带 ping + 有界重连）。
- **工具**：生产 `RuntimeToolCatalog` 注册 29 个稳定 ToolSpec。只读工具自动执行；可逆、低风险的内部写入可标 `REVERSIBLE_AUTO_WRITE`，但只有在 inverse、原子审计和可见撤销三项均就绪时才自动，否则降级到确认；其他写工具经 `CapabilityRouter` + 确认门。Binding/Executor 文件数量不作为架构契约。
- **技能**：6 内置（日程协调/联系人完善/个人 CRM/生活助理/一起安排/偏好记忆）+ SCENE 级第三方包签名预留。

## 第六部分 · 采集与执行通道

### 采集（Collect）
| 通道 | 实现 | 状态 |
|---|---|---|
| 社交软件通知 | `ZhiBanNotificationListenerService` → `stageNotificationCandidate` | ✅ |
| 发出的消息 | `OutgoingMessageAccessibilityService`（白名单、默认关、不点击/不代发/截图不保存） | ✅ |
| 语音 | `RECORD_AUDIO` + StepFun ASR | ✅ |
| 文本分享进入 | `MainActivity.acceptSharedText`（仅收 `ACTION_SEND + text/plain`） | ✅ |
| 通话记录 | `READ_CALL_LOG` + `AndroidCallLogSource` 增量对账 → 标准化匹配联系人 → 写独立 `call_records` → 联系人时间线 | ✅ 已实现；双卡仍需独立设备验收 |
| 通话挂断备注 | Receiver/`TelephonyCallback` → 唯一 Worker 对账 → 应用内待备注 + 私密通知 → 文字或 `CloudAsrGateway.transcribe` → `call_notes`/FactIndex | ✅ 已实现；真实拨入拨出与 ASR 公网仍需真机人工验收 |

> **通话方案（详见 `docs/通话采集设计.md`）**：普通第三方 App 不依赖受限/灰色能力获取电话双方音轨，知伴明确**不做通话录音**。改走“通话记录元数据 + 挂断后用户主动语音备注”——用 `READ_CALL_LOG` 采“和谁/何时/多久”，挂断时提示用户主动录一小段备注，经现有 ASR 转文字挂到联系人。

### 执行（Act）
- **风险分级**：`ActionPolicy` 四档 `READ_ONLY 自动 / REVERSIBLE_AUTO_WRITE 条件自动且可撤销 / WRITE_CONFIRMATION_REQUIRED / HIGH_RISK 强确认`。对外发送、删除和不可逆操作不得进入自动写；当前生产 ToolSpec 尚未使用 `HIGH_RISK`。
- **对外通道**：`AgentConversationRoute` 分享回复 + `CommunicationHandoffLauncher` 按平台 `ACTION_SEND`。
- **已启用**：`ActionPolicy` 的“低风险自动写 + 可回滚”档已用于互动摘要、联系人标签新增、高置信且无冲突的消息日程、CRM 候选线索、CRM 活动追加和 CRM 下一步动作创建；三重门缺一即降级确认。

## 第七部分 · 隐私与安全体系

### 出站安全三件套（按通道显式收口）
1. **模型消息**：生产 `ProviderAdapter` 最外层包 `PolicyEnforcingProviderAdapter`，任何 `provider.stream()` 先经过 `OutboundDataPolicy`。策略区分 `USER_AUTHORED`（用户主动发送，不脱敏）/`AUTO_RETRIEVED`（按敏感度）/`TOOL_OBSERVATION`；自动补充的 `SENSITIVE` 整块省略，`PERSONAL` 经 `OutboundPiiRedactor` 脱敏。
2. **非模型 Transport**：ASR、MCP、Embedding 等必须在最终网络调用点显式经过 `OutboundExportGate`。LLM/RERANK 当前豁免同意；ASR/MCP/Embedding 默认关，需授权。
3. **审计**：所有出口只记录通道、用途、敏感度、数量、大小和结果等元数据，不记录原文或音频。
> `PolicyEnforcingProviderAdapter` 只能结构性兜住模型 Provider；新增二进制或远程工具 Transport 不会自动受管辖，必须接 Gate 并补“无 Gate 不得出网”的测试。

### 本地加密
- **SQLCipher**：32 字节随机密钥，AndroidKeyStore AES-GCM 包裹存 SP，明钥不落盘；明文→密文迁移在后台线程。
- **凭据**：`KeystoreCredentialVault`（keyVersion 轮换，明文 `fill(0)`）。
- **审计**：`AppPrivateOutboundAuditStore`（只存 SHA-256 digest + 类别 + 计数，不存原文，可一键清除）。

### 隐私纪律
系统自动检索的敏感原文默认不发外部、不打日志，审计只存元数据。用户主动输入、主动选择的附件或主动录制的语音，可在当次动作和通道授权下出站；对外发送由用户最后把关。

## 第九部分 · 如何扩展（照骨架填格子）

这是开发最常用的一节——知伴是"骨架先行、加法友好"，加功能不动底层，只在对应格子注册/接入。

### 加一个场景能力（Scene）
1. 在 `SkillTab` 的 `sceneCapabilities` 注册一张 `SceneCapability(level=SCENE)` 卡片。
2. 在 `SkillContracts` 定义对应技能（triggerIntents + requiredTools + planningInstruction）。
3. 实现该场景的数据模型（新表 + 迁移）与 `*ToolBinding`。
4. 复用统一关系库，**不要复制联系人数据**（原则：场景复用统一关系库）。

### 加一个工具（Tool）
1. 在 `agent:tools` 定义或复用 `RuntimeToolSpec`（name/params/risk），并在 `RuntimeToolCatalog` 注册。
2. 在 `app/runtime/tool` 实现需要 Room/Android 能力的 `*ToolBinding`/`*ToolExecutor`；纯逻辑才留在 JVM 子模块。
3. 普通写工具标 `WRITE_CONFIRMATION_REQUIRED`；只有能提供 inverse、原子审计和可见撤销三项能力的内部低风险写入才可标 `REVERSIBLE_AUTO_WRITE`。
4. 幂等：复用统一幂等键（`canonicalToolIdempotencyKey`）。

### 加一个采集通道
实现对应系统服务/读取器 → 选择与领域匹配的候选表或事实表 → 走统一“判断”链。通知/分享文本可用 `stageNotificationCandidate`；通话等结构化数据应使用独立领域模型，不强塞通知候选。注意权限与采集描述克制。

### 加一个出站通道
模型 Provider 必须经 `PolicyEnforcingProviderAdapter`；ASR/MCP/Embedding 等非模型 Transport 必须在最终网络调用前显式经 `OutboundExportGate`。敏感内容按用途和敏感度标记，并补出口级测试。

### 改模块归属
物理移动 .kt 到对应子模块 `src/main/kotlin` → 删 app 旧文件 → 为该模块新增/更新 `verifyAgentModuleBoundaries` Rule → 跑 `check`。

## 第十部分 · 施工纪律

1. **读最终调用点再下结论**：任何"这里有/没有 X"先 grep 到调用点。
2. **取消语义**：关键 suspend 链路显式 rethrow `CancellationException`。suspend 函数体内的泛型 `catch`（`Throwable`/`Exception`/`RuntimeException`）由 `auditCancellationSafety` 门禁——无可见 rethrow 即阻断 `check`；非 suspend 函数内的泛型 `catch` 不计（不可能发生取消）。包裹 suspend 调用必须用 `runSuspendCatching`，不得用会吞掉取消的 `runCatching`。
3. **模块边界**：遵守每个子模块的 Gradle 依赖和边界 Rule；新增模块/改归属必须显式更新守卫。
4. **隐私纪律**：自动补充的敏感原文默认不出站、不打日志，审计只存元数据；模型出口走 Policy Adapter，非模型出口显式走 Export Gate。
5. **数据纪律**：多表写用事务；按领域使用 tombstone/软删/状态，并同步维护检索投影；合并/删除检索统一过滤。
6. **测试纪律**：新功能带抓回它的测试；优先覆盖跨域接缝。
7. **文档纪律**：架构决策写 `docs/adr/`；本手册为总纲，代码与手册冲突时以代码为准并回写手册。
