# 通话采集 · 施工设计

> 目标：把“和谁、何时、通了多久、用户主动补充了什么”接入知伴的核心时间线和个人 CRM。
> 约束：普通第三方 App 不录制通话语音流，不使用灰色权限或免提录音；通话内容只来自用户挂断后主动输入或录制的备注。
> 状态：2026-08-05 已按当前代码实施；SM-W7023 权限读取探针通过，真实拨入/拨出与公网 ASR 仍需人工验收。

---

## 一、能力边界

| 子功能 | 采集内容 | 权限 | 结果 |
|---|---|---|---|
| A. 通话记录 | 系统 CallLog 中的号码、时间、时长、类型、电话账户 | `READ_CALL_LOG` | 写入 `call_records`，匹配联系人并投影到统一时间线 |
| B. 挂断后“顺手一记” | 用户主动输入的文字或主动录制的语音备注 | `READ_PHONE_STATE`；语音另需 `RECORD_AUDIO` 与 ASR 出站授权 | 写入 `call_notes`，进入时间线与 FactIndex；用户明确选择商机后可关联 CRM 活动 |

以下内容明确不做：

- 不申请或使用 `VOICE_CALL`、`VOICE_COMMUNICATION`、`CAPTURE_AUDIO_OUTPUT`。
- 不在后台启动麦克风，不把电话广播中的号码直接当成可靠通话记录。
- 不因为号码相似自动挂错联系人；未匹配或多匹配时保留候选。
- 不把每一通电话自动复制成 CRM 活动。

## 二、实施硬闸：先验证权限可获得性

`READ_CALL_LOG` 是 Android hard-restricted 权限。产品当前按侧载分发，但每种安装器/OEM 组合仍必须真机验证，不能只看运行时授权弹窗。

第一步只实现最小权限探针：

1. Manifest 声明 `READ_CALL_LOG`，设置页提供独立开关与用途说明。
2. 用户主动开启后请求权限；拒绝不影响联系人、日历、问问等功能。
3. SM-W7023 上检查最终 permission flag/AppOps，并只验证 `CallLog.Calls` 可查询，不在日志、报告或截图中输出真实号码。
4. 若当前安装方式不能让应用实际持有权限，停止后续 A/B 开发，先解决安装器 allowlist；不得伪造“已授权”。

Google Play 上架不按个人 CRM 可获得企业 CRM 例外设计；若未来改变分发方式，重新做权限政策评审。

## 三、权限分层

```xml
<uses-permission android:name="android.permission.READ_CALL_LOG" />
<uses-permission android:name="android.permission.READ_PHONE_STATE" />
```

- 子功能 A 只请求 `READ_CALL_LOG`。读取历史与增量对账不依赖电话状态权限。
- 子功能 B 用户开启“挂断后提醒”时才请求 `READ_PHONE_STATE`。
- 用户点击“语音备注”时才申请 `RECORD_AUDIO`；文字备注不需要麦克风。
- 云端 ASR 使用独立的 `allowCloudSpeech` 同意门，默认关闭。
- Android 13 通知权限可能被拒绝，因此通知只是应用内待备注状态的一个投影，不能是唯一入口。

设置入口需分别显示：未开启、系统未授权、安装器不允许、已开启。权限被撤回时同步停止读取/监听，但保留用户已经确认保存的本地资料。

## 四、子功能 A：CallLog 增量对账

### 4.1 系统读取层

`AndroidCallLogSource` 位于 `app` Android 集成层，查询 `CallLog.Calls.CONTENT_URI`。读取：

- `BaseColumns._ID`
- `CallLog.Calls.NUMBER`
- `CallLog.Calls.NUMBER_PRESENTATION`
- `CallLog.Calls.TYPE`
- `CallLog.Calls.DATE`
- `CallLog.Calls.DURATION`
- `CallLog.Calls.LAST_MODIFIED`
- `CallLog.Calls.PHONE_ACCOUNT_ID`
- `CallLog.Calls.PHONE_ACCOUNT_COMPONENT_NAME`

保留系统原始 `TYPE`，再派生 UI 类别。除 `OUTGOING/INCOMING/MISSED/REJECTED` 外，还要能容纳 `BLOCKED/VOICEMAIL/ANSWERED_EXTERNALLY/UNKNOWN`，不能静默丢弃未来或 OEM 类型。

号码展示受 `NUMBER_PRESENTATION` 控制。私密/未知/不可用号码不得伪造为普通号码，也不参与联系人自动匹配。

### 4.2 统一号码归一化

复用并增强现有 `normalizeContactPhone`，使通讯录导入、用户保存、通知匹配、去重和 CallLog 使用同一实现。至少满足：

- `138-0013-8000` 与 `13800138000` 相等。
- 在中国号码上下文中，`+86 138 0013 8000` 与 `13800138000` 相等。
- 分机号、私密号码、少于合理长度的号码不产生高置信自动匹配。

禁止为 CallLog 单独复制另一套归一化函数。

### 4.3 领域表

新增 SQLCipher Room 表 `call_records`，作为通话元数据唯一事实源。建议字段：

```text
callRecordId                  本地稳定 ID
source                        ANDROID_CALL_LOG
providerRowId                 CallLog._ID
rawNumber                     原号码；仅加密库内保存
normalizedNumber              统一归一化结果，可空
numberPresentation            系统展示级别
systemType                    系统原始类型
direction                     派生 UI 类别
startedAtEpochMs
durationSeconds
lastModifiedEpochMs
phoneAccountId                不透明快照，可空
phoneAccountComponentName     不透明快照，可空
linkedContactId               可空；联系人删除时 SET_NULL
linkState                     MATCHED / UNMATCHED / AMBIGUOUS / USER_LINKED
sourceStatus                  ACTIVE / SOURCE_DELETED
notePromptState               NONE / PENDING / DISMISSED / COMPLETED
createdAtEpochMs / updatedAtEpochMs
```

唯一约束优先使用 `(source, providerRowId)`。如果个别 Provider 无 `_ID`，才使用包含号码展示级别、标准化号码、时间、类型和电话账户的稳定 fallback fingerprint。

系统观察到的通话不伪装成用户确认：当前以 `source=ANDROID_CALL_LOG`、`linkState` 和 `linkSource` 表达来源，表内没有虚假的 `userConfirmed` 字段。用户手动关联联系人时再记录用户确认和可撤销变更。

### 4.4 增量与幂等

- 游标保存最后成功提交的 `LAST_MODIFIED`，并保留重叠窗口重新查询。
- 同一个游标值可有多行，不能只用单个最大 `DATE` 丢弃同毫秒记录。
- 先在一个 Room 事务里 upsert 全批数据、联系人关联状态及派生投影，成功后才推进 DataStore 游标。
- 同一批或 Worker 重试不得产生重复记录。
- 权限撤回、SecurityException、Provider 暂不可用返回固定降级码，不记录异常 message、SQL 或号码。

### 4.5 对账触发

CallLog 是正确性来源，电话状态只是低延迟提示：

- 用户首次授权后执行一次有限范围初始导入。
- App 启动/回前台、采集设置页手动刷新时增量对账。
- 唯一 PeriodicWork 做兜底对账；它受 Doze 影响，不承诺准点。
- Worker 在权限撤回时安全结束，不无限 retry。

不要把对账绑死在日历页或关系页的 Composable 重组上。

## 五、联系人关联与统一时间线

`call_records.linkedContactId` 通过 `ContactKnowledgeDao.findContactsByMethod("PHONE", normalizedValue)` 取得全部候选后匹配：

- 唯一高置信号码命中：允许系统关联，当前来源为 `NORMALIZED_PHONE`。
- 无命中：保留 `UNMATCHED`，在应用内候选区提示用户。
- 多命中或冲突：标记 `AMBIGUOUS`，必须用户选择。
- 联系人后续创建、合并、撤销合并或删除后可重新解析 canonical contact；不得复制联系人资料。

不把原始 CallLog 行写进 `relationship_events`。统一时间线通过查询/投影组合：

- `call_records`
- `call_notes`
- `relationship_events`
- `crm_activities`
- 已发生的日历事件

这样既保留每种事件的领域字段，又给 UI 和 Agent 一个统一“和谁、何时、发生什么”的读取面。

## 六、子功能 B：挂断后“顺手一记”

### 6.1 触发架构

采用“双层触发 + 对账兜底”，不使用常驻前台服务：

1. Manifest Receiver 接收 `TelephonyManager.ACTION_PHONE_STATE_CHANGED`，只读取状态，不使用广播号码落库。
2. API 31+ 在进程存活时为每个 active subscription 使用 `createForSubscriptionId()` 注册 `TelephonyCallback.CallStateListener`；API 26-30 如需前台低延迟才使用 `PhoneStateListener`。
3. 观察到 `IDLE` 后，入队唯一 OneTimeWork，短暂延迟并有限重试，等待系统电话应用把最终记录写入 CallLog。
4. Worker 增量对账并找出新出现的 CallLog 行；广播重复、乱序或进程重启不能产生重复提示。
5. App 被强制停止/OEM 杀进程而漏触发时，下次前台/周期对账恢复记录；“立即提示”允许降级为应用内待处理项。

同时持有 `READ_CALL_LOG` 和 `READ_PHONE_STATE` 时，系统电话状态广播可能发送两次且顺序不保证，因此必须使用 unique work + CallLog providerRowId 去重。

### 6.2 双卡

TelephonyCallback 按 active subscription 分别注册，CallLog 保存 `PHONE_ACCOUNT_ID/COMPONENT_NAME` 快照，但不假设它们等于 subscriptionId 或永久不变。

当前 SM-W7023 实测为 Android 13 单卡配置，只能完成单卡验收。双卡必须使用另一台 DSDS 设备单独验收：两卡拨入、两卡拨出、默认卡切换、通话中切换数据卡、SIM 更换后旧记录展示。

### 6.3 待备注状态和通知

新导入的、符合产品条件的通话在 `call_records.notePromptState` 进入 `PENDING`。应用内 CRM/关系时间线展示待处理入口；通知只作为可选投影：

- 用户禁止通知时，待处理项仍可在 App 内看到。
- 锁屏公开版本只显示“有一条通话待补充”，使用 `VISIBILITY_PRIVATE`；联系人、号码和时长只在解锁后的私有内容中显示。
- 当前只有已接通且有时长的呼入/呼出进入通话备注；未接/拒接仍保留为通话记录，不误提示填写“聊了什么”。“安排回拨”候选留给后续日程判断链。
- 用户忽略/关闭后写 `DISMISSED`，不重复轰炸。

### 6.4 备注与 ASR 首次授权

用户点“补充备注”后先提供文字输入；选择语音时按以下顺序：

1. 调用 `CloudAsrGateway.availability()`。
2. 若为 `CONSENT_REQUIRED`，在当前流程原地展示上云说明：当前服务、音频用途、发送内容、审计范围和临时文件保留策略。
3. 用户同意后持久化 `allowCloudSpeech=true`；拒绝后停留在文字备注，不上传。
4. 再请求 `RECORD_AUDIO`；仅在用户点击开始后录音。
5. `CloudAsrGateway.transcribe()` 在最终调用点再次经过 `OutboundExportGate`。
6. 成功后展示转写文本供用户编辑并保存；转写结果不能直接替用户生成对外消息。

ASR 上传的是用户主动录制的音频，无法用文本正则脱敏。它的保护机制是显式同意、最小用途、最终出口 Gate 和不含原文的元数据审计，而不是 `OutboundDataPolicy` 对音频内容做脱敏。

弱网失败时音频只保存在应用私有临时目录，允许用户重试或删除；设定明确 TTL，过期自动清除，不能无限保留。

### 6.5 备注领域模型与检索

新增 `call_notes`：

```text
callNoteId / callRecordId / noteText
source(TYPED|SYSTEM_SPEECH|CLOUD_ASR) / asrProvider?
createdAtEpochMs / updatedAtEpochMs
```

保存、编辑、删除备注和维护 FactIndex 必须在统一事务边界内完成：

- `call_notes` 是备注原文的事实源。
- Fact 使用 `factType=CALL_NOTE`、`sourceType=USER_CALL_NOTE`、`sourceRef=callRecordId`，使 Agent 本地 FTS 可检索。
- 删除或撤销备注时同步撤销 Fact/FTS/Embedding 投影。
- 备注自动进入联系人时间线；只有用户明确选择商机，或 Agent 给出可回滚的低风险内部关联后，才建立 CRM activity/关联，不能按号码猜商机。

## 七、隐私与安全

1. 通话记录、号码、备注全部进入 SQLCipher，不写 WorkManager inputData、不打日志。
2. Worker/Receiver 只传 `callRecordId`、游标或固定原因码，不传标题、姓名、号码或备注。
3. 权限独立授权、随时关闭；关闭后停止新增采集，不影响其它功能。
4. 私密/未知号码不参与联系人自动匹配。
5. 通话元数据默认留在本机；备注进入模型上下文时标 `AUTO_RETRIEVED` 并经过模型出站策略。
6. 用户主动录制的音频只在 ASR 明确同意后上传，并进入出站元数据审计。
7. 对外回复仍必须由用户完成最后发送。

## 八、测试与验收

### 权限探针

- SM-W7023 上运行时授权后，`READ_CALL_LOG` 最终状态和 Provider 查询均成功。
- 拒绝、撤回、安装器不允许三种状态可区分，且其它功能正常。
- 报告与测试日志无真实号码。

### 子功能 A

- 重复同步、Worker 重试、同毫秒多记录均不重复。
- `LAST_MODIFIED` 更新能更新原记录，游标仅在事务成功后推进。
- 中国号码格式统一；私密/未知/短号码不误匹配。
- 唯一联系人自动关联；零命中和多命中进入正确候选状态。
- 通话类型和 phone account 元数据不丢失。
- 联系人合并、撤销和删除后时间线引用正确。

### 子功能 B

- 单次电话状态变化即使收到重复广播，也只产生一次对账和一次待备注项。
- CallLog 延迟写入时有限重试能找到记录；超时后由下次对账恢复。
- 禁止通知时应用内入口仍存在；锁屏不泄露联系人信息。
- ASR 默认关闭；首次原地同意后才能上传。拒绝时文字备注可用。
- 取消备注不写记录；弱网可重试或删除；临时音频按 TTL 清理。
- 备注保存/编辑/删除与 FactIndex 同步，Agent 检索能召回且删除后不能召回。

### 构建与设备

- 每阶段运行 `./gradlew check assembleRelease`。
- SM-W7023 完成单卡拨入、拨出、未接、拒接、权限撤回、通知拒绝、ASR 同意/拒绝测试。
- 当前设备不能证明双卡通过；双卡列为独立且不可跳过的后续设备矩阵。
- 通话采集包和 Manifest 无 `VOICE_CALL`、`CAPTURE_AUDIO_OUTPUT` 等电话音轨采集能力。问问的实时语音对话可继续使用面向麦克风的 `VOICE_COMMUNICATION` audio source；它不属于电话通话录音链路。
